## Επεξήγηση εκφώνησης 

Μας δίνεται ένας δυαδικός δισδιάστατος πίνακας και κάποιες πράξεις τις μορφής: να αντιστραφούν όλες οι δυαδικές τιμές στον υποπίνακα με άκρα από το σημείο $$(a, c)$$ έως το $$(b, d)$$. Μετά από κάθε πράξη πρέπει να πούμε με πόσους τρόπους μπορούν να γίνουν όλα τα στοιχεία του πίνακα $$0$$ με πράξεις της μορφής: (1) διαλέγουμε μια στήλη και αντιστρέφουμε όλα της τα στοιχεία ή (2) διαλέγουμε μία γραμμή και αντιστρέφουμε όλα της τα στοιχεία.

Παρακάτω θα δούμε μία λύση με brute force, έπειτα θα κάνουμε μία βασική παρατήρηση που λέει ότι ο πίνακας είναι αντιστρέψιμος αν και μόνο αν όλες οι γραμμές είναι είτε ανά δύο ίσες είτε η μία είναι αντίστροφη της άλλης. Αυτή την παρατήρηση θα την χρησιμοποιήσουμε για να λύσουμε το πρόβλημα πρώτα για σημειακά updates και μετά θα δούμε μία λύση με hash που λύνει το πρόβλημα στην γενική περίπτωση.

## Brute force 

Η brute force λύση είναι δοκιμάσουμε όλες τις δυνατές πράξεις που μπορεί ο Τάκης να κάνει. Για κάθε γραμμή και κάθε στήλη μπορούμε είτε να την αντιστρέψουμε είτε όχι. Καθώς υπάρχουν $$N$$ γραμμές και $$N$$ στήλες, υπάρχουν συνολικά $$2^N \cdot 2^N = 2^{2N}$$ δυνατές πράξεις. Ο παρακάτω κώδικας ελέγχει όλες τις δυνατές πράξεις.

## Βασική παρατήρηση

Κάνουμε τις εξής παρατηρήσεις, τις οποίες θα τις συνδυάσουμε για λάβουμε την βασική παρατήρηση.

**Παρατήρηση 1:** Αν ένα κελί είναι $$1$$ τότε πρέπει να αντιστρέψουμε είτε την γραμμή $$r$$ είτε την στήλη $$c$$ (αλλά όχι και τις δύο).

**Παρατήρηση 2:** Αν υποθέσουμε ότι δεν θα αντιστρέψουμε μία γραμμή $$r = 1$$, τότε όλες τις στήλες $$c$$ με `A[r][c] = 1` πρέπει να τις αντιστρέψουμε και όλες τις υπόλοιπες *δεν* πρέπει να τις αντιστρέψουμε.

**Βασική παρατήρηση:** Για να είναι ο πίνακας αντιστρέψιμος πρέπει όλες οι γραμμές να είναι ίδιες με την $$r = 1$$ ή ίσες με την αντίστροφή της. Έπεται ότι είτε δεν υπάρχει τρόπος να αντιστραφεί ένας πίνακας είτε υπάρχουν ακριβώς δύο τρόποι.

## Λύση σε $$O(N + (K + Q)N)$$ για σημειακά updates

Η επόμενη παρατήρηση είναι άμεση συνέπεια της [αρχής του περιστερώνα](https://el.wikipedia.org/wiki/%CE%91%CF%81%CF%87%CE%AE_%CF%84%CE%BF%CF%85_%CF%80%CE%B5%CF%81%CE%B9%CF%83%CF%84%CE%B5%CF%81%CF%8E%CE%BD%CE%B1).

**Παρατήρηση:** Όταν $$a_i = b_i$$ και $$c_i = d_i$$, τότε υπάρχει μία γραμμή $$r$$ της οποίας τα στοιχεία δεν ανανειώνονται πάνω από $$(K + Q)/N$$ φορές. 

Επομένως, θεωρούμε αυτή την γραμμή ως γραμμή αναφοράς και κρατάμε για κάθε άλλη γραμμή σε πόσα στοιχεία διαφέρει από την γραμμή αναφοράς. Κάθε φορά που αλλάζουμε ένα στοιχείο εκείνης της γραμμής μπορούμε σε $$O(1)$$ χρόνο ανανεώσουμε το πλήθος των διαφορετικών στοιχειών καθώς και το πλήθος των γραμμών ίσων (ή αντίθετων) με την γραμμή αναφοράς.

Όταν ανανεώνουμε ένα στοιχείο της γραμμής αναφοράς πηγαίνουμε σε όλες τις άλλες γραμμές και ανανεώνουμε τα στοιχεία τους σε χρόνο $$O(N)$$. 

{% include code.md solution_name='flips_quadratic.cc' start=33 end=63 %}

Επομένως, επειδή δεν υπάρχουν πάνω από $$(K+Q)/N$$ πράξεις στην γραμμή αναφοράς, συνολικά χρειαζόμαστε $$O(Q \cdot 1 + (K+Q)/N \cdot N) = O(K + Q)$$ χρόνο για τις πράξεις και $$O(N)$$ χρόνο για την αρχικοποίηση. Αυτό είναι αρκετό για να περάσει τα τρία πρώτα υποπροβλήματα.

Μπορείτε να δείτε ολόκληρο τον κώδικα [εδώ]({% include link_to_source.md solution_name='flips_quadratic.cc' %})).

## Λύση με hash

Μία εναλλακτική για να συγκρίνουμε αν δύο γραμμές είναι ίσες είναι να υπολογίσουμε ένα [hash](https://el.wikipedia.org/wiki/%CE%A3%CF%85%CE%BD%CE%AC%CF%81%CF%84%CE%B7%CF%83%CE%B7_%CE%BA%CE%B1%CF%84%CE%B1%CE%BA%CE%B5%CF%81%CE%BC%CE%B1%CF%84%CE%B9%CF%83%CE%BC%CE%BF%CF%8D) για την κάθε γραμμή και να ελέγξουμε αν αυτά τα δύο hash είναι ίδια. Πιο συγκεκριμένα, θα χρησιμοποιήσουμε έναν αριθμό 64-bit για hash, που αναπαριστά τις στήλες που είναι 1 στην κάθε γραμμή και θα ελέγξουμε αν οι τιμές αυτές είναι ίσες. Η ιδιότητα που έχουν τα hash είναι ότι δύο ίδιες γραμμές θα έχουν το ίδιο hash, ενώ δύο διαφορετικές γραμμές θα έχουν διαφορετικό hash με μεγάλη πιθανότητα.[^1]

[^1]: Συγκεκριμένα, αν υποθέσουμε ότι τα hash για τις στήλες τα έχουμε διαλέξει τυχαία και ανεξάρτητα μεταξύ τους, τότε η πιθανότητα δύο σύνολα να έχουν ένα ίδιο bit είναι $$<1/2$$. Άρα αν χρησιμοποιήσουμε 64-bit η πιθανότητα να έχουν όλα τα ίδια bits είναι μικρότερη από $$1/2^{64}$$. Αυτό σημαίνει ότι μπορούμε να κάνουμε $$10^9$$ συγκρίσεις τιμών hash και η πιθανότητα λάθους να παραμένει μικρότερη του $$10^9/2^{64} < 10^{-10}=0.0000000001$$.


Θα δημιουργήσουμε το hash με τον εξής τρόπο:
 1. Διαλέγουμε έναν αριθμό $$h_i$$ για κάθε στήλη $$i$$ (κανονικά θα θέλαμε να είναι τυχαίοι, αλλά θα χρησιμοποιήσουμε μία γεννήτρια τυχαίων αριθμών, την `std::mt19937`).
 2. Για κάθε γραμμή $$i$$ βρίσκουμε τις τιμές $$h_{j_1}, \ldots, h_{j_k}$$ για τις $$k$$ στήλες $$j_1, \ldots, j_k$$ στην γραμμή $$i$$ που είναι $$1$$.
 3. Υπολογίζουμε την τιμή $$h_{j_1} \oplus \ldots \oplus h_{j_k}$$, όπου $$\oplus$$ είναι το [xor](https://el.wikipedia.org/wiki/%CE%94%CF%85%CF%86%CE%B9%CE%BF%CF%84%CE%B5%CE%BB%CE%AE%CF%82_%CF%80%CF%81%CE%AC%CE%BE%CE%B7#%CE%94%CF%85%CF%86%CE%B9%CE%BF%CF%84%CE%B5%CE%BB%CE%AE%CF%82_%CE%B1%CF%80%CE%BF%CE%BA%CE%BB%CE%B5%CE%B9%CF%83%CF%84%CE%B9%CE%BA%CE%AE_%CE%B4%CE%B9%CE%AC%CE%B6%CE%B5%CF%85%CE%BE%CE%B7) δύο αριθμών.

Για παράδειγμα, αν χρησιμοποιήσουμε εξής τιμές $6$-bit για hash
* $$h_1 = \texttt{011010}$$,
* $$h_2 = \texttt{111001}$$,
* $$h_3 = \texttt{011101}$$,
* $$h_4 = \texttt{101001}$$,
* $$h_5 = \texttt{001101}$$,
* $$h_6 = \texttt{011100}$$,
* $$h_7 = \texttt{110010}$$,
* $$h_8 = \texttt{001100}$$,

τότε η γραμμή που έχει $1$ στις στήλες $2$, $4$, $5$, $7$, $8$ θα έχει hash $$h$$ ίσο με

$$\\

\begin{align*}
        & \texttt{111001} \quad (=h_2)\\
\oplus\ & \texttt{101001} \quad (=h_4)\\
\oplus\ & \texttt{001101} \quad (=h_5)\\
\oplus\ & \texttt{110010} \quad (=h_7)\\
\oplus\ & \texttt{001100} \quad (=h_8)\\
 \hline
= \ & \texttt{100011} \quad (=h)
\end{align*}

\\$$

(Το $$k$$-οστό bit στο αποτέλεσμα είναι $$1$$ αν και μόνο αν υπάρχει μονό πλήθος $$1$$ στα $$k$$-οστά bit των τιμών εισόδου.)

<center>
<img alt="Παράδειγμα γραμμής με 01011011." src="/assets/38-c-flips-example.svg" width="280px">
</center>


Το xor έχει την εξής ιδιότητες:
 * $$x \oplus x = 0$$ (δηλαδή ο $$x$$ είναι ο αντίστροφος του εαυτού του ως προς το xor),
 * $$x \oplus y = y \oplus x$$ και $$x \oplus (y \oplus z) = (x \oplus y) \oplus z$$ (δηλαδή δεν έχει σημασία η σειρά που προσθέτουμε ή αφαιρούμε στοιχεία).
 
Για παράδειγμα, αν θέλουμε να αντιστρέψουμε την τιμή στην στήλη $$h_5$$ απλά κάνουμε

$$h \oplus h_5 = \texttt{100011} \oplus \texttt{001101} = \texttt{101100}$$

που είναι ίσο με $$h_2 \oplus h_4 \oplus h_7 \oplus h_8$$.[^2]

[^2]: Αυτό συμβαίνει καθώς $$h \oplus h_5 = (h_2 \oplus h_4 \oplus h_5 \oplus h_7 \oplus h_8) \oplus h_5 = (h_2 \oplus h_4 \oplus h_7 \oplus h_8 \oplus h_5) \oplus h_5 = (h_2 \oplus h_4 \oplus h_7 \oplus h_8) \oplus (h_5 \oplus h_5)$$.
 
Αυτός ο τρόπος μας επιτρέπει να προσθέτουμε και να αφαιρούμε εύκολα (και σε $$O(1)$$ χρόνο) μία στήλη από το hash μίας γραμμής, δηλαδή να ανιστρέψουμε την τιμή ενός κελιού. Επίσης το σύνολο $$(h_1 \oplus \ldots \oplus h_N) \oplus x$$ είναι το σύνολο που περιέχει όλες τις στήλες που δεν είναι στο $$x$$. Άρα καθώς έρχονται τα σημειακά updates, κρατάμε το hash της κάθε γραμμής και ένα map με τον αριθμό των φορών που εμφανίζεται το κάθε hash. Αν μετά από ένα update υπάρχει μία τιμή στο set ή δύο τιμές όπου η μία είναι αντίστροφη της άλλης, τότε μπορούμε να αντιστρέψουμε τον πίνακα. Διαφορετικά δεν μπορούμε.

## Λύση με διαφορές hash 

Για να υποστηρίξουμε updates σε διαστήματα, χρειαζόμαστε δύο επιπλέον τεχνικές:
1. Για την αντιστροφή όλων των στηλών που ανήκουν σε ένα διάστημα $$[i, j]$$.
2. Για την αντιστροφή όλων των γραμμών σε ένα διάστημα.

**Τεχνική 1η:** Κρατάμε τα xor $$p_0, p_1, \ldots, p_N$$ των προθεμάτων των hash $$0, h_1, \ldots, h_N$$, δηλαδή 

$$p_i = h_1 \oplus h_2 \oplus \ldots \oplus h_i.$$

Έτσι, η ανανέωση των hash για το διάστημα $$[i, j]$$ γίνεται παίρνοντας xor με την τιμή 

$$D = h_i \oplus \ldots \oplus h_j = p_j \oplus p_{i-1}.$$

**Τεχνική 2η:** Αντί να κρατάμε ένα σύνολο με τις τιμές των hash, κρατάμε τις διαφορές $$d[i]$$ των hash των διαδοχικών γραμμών $$i$$ και $$i+1$$, και ξανά αρκεί να υπάρχουν δύο τιμές για αυτές τις διαφορές (η μία να είναι $$0$$, αντιστοιχεί σε όλα τα στοιχεία να είναι ίδια, και η άλλη όλα $$1$$, που ανιτστοιχεί σε όλα τα στοιχεία να είναι διαφορετικά).

Επιπλέον αυτή η τεχνική μας επιτρέπει να αντιστρέψουμε ένα διάστημα $$[i, j]$$ αλλάζοντας μόνο τα $$d[i-1]$$ και $$d[j]$$, σε $$d[i-1] \oplus D$$ και $$d[j] \oplus D$$ αντίστοιχα. Οι διαφορές των υπόλοιπων γραμμών παραμένουν οι ίδιες.
